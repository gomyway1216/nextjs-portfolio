# B12：色を均衡させた純粋な depth 12 学習を、1案だけ事前登録する

_2026年7月25日_

[English version](./blog-shogi-balanced-pure-depth12-pilot.en.md)

## 何を確かめるか

次の実験は、既存の alpha-0.50 HalfKP を出発点に、やねうら王 depth 12 の `cp` だけを教師として1 epoch更新する。候補は **B12-alpha050-balanced-pure-v1 の1つだけ**。学習率、seed、epoch数を見てから増やすことはしない。

目的は「静的な一致率を上げること」ではない。候補と現在のライブ版を直接対局させ、棋力が改善する兆候を短い実験で棄却または確認することだ。

## 入力とデータ

入力はローカル実物から、容量・行数・SHA-256を省略せず再確認した。教師はレーティング3000以上の強い棋譜から作った既存 depth 12 データで、元の分割には対局・意味的局面の重複がない。

- 学習元：800,000局面（先手番402,090、後手番397,910）
- 検証元：3,000局面（先手番1,484、後手番1,516）
- 学習用：決定的に抽出した200,000局面（各手番100,000）
- 検証用：2,968局面（各手番1,484）

抽出は固定seedとSHA-256順位で行う。同じ入力なら同じ行が選ばれる。派生データはまだ作っていないため、そのSHA-256は計画上 `null` のままにした。作成後、全検査に合格してからmanifestに確定値を書く。

## 固定した学習

学習は HalfKP-factor の全パラメータを1 epochだけ更新する。batch 1024、learning rate `1e-5`、seed 42、sigmoid value loss、WDL混合0。順位・方策・兄弟局面・勝敗教師は使わない。候補はepoch 1だけで、検証値を見た「当たり候補選び」はしない。

対局前に、有限値、int16 export、200以上の固定局面でのPyTorch・TorchScript・WASM完全一致、量子化誤差、ライブファイル不変を確認する。検証lossや教師一致率は診断値であって棋力判定には使わない。

## 成否と停止条件

正しさの検査を通った候補だけを、ライブ版と56局対局させる。新しい28組の色違い局面、1手1.5秒、7組並列、定跡なし、mate solverなし。技術故障0・違法手0が必須で、候補が112 halfpoints中62以上なら通過とする。途中停止は数学的に到達不能になった場合だけ。

未達ならB12系はそこで止め、800k化、depth 16化、seedや学習率の追加探索へ自動で広げない。通過しても認めるのは、別途事前登録する独立96局の確認だけである。

## 事前登録時点

ここまでが実行前に固定した計画である。この時点ではデータ抽出、学習、対局は始めておらず、完全な入力SHA、固定条件、停止規則を[機械可読プラン](../ml/protocols/halfkp-alpha050-balanced-pure-depth12-v1-plan.json)に記録した。

## 実行結果

決定的な抽出は6.45秒で完了し、学習用200,000局面は先後各100,000、検証用2,968局面は先後各1,484になった。予定した手番均衡を満たし、1 epoch学習も完走した。学習処理全体は12.1秒、そのうちepoch本体は4.8秒だった。

静的な検証値は、lossが`0.062198`から`0.053685`、MAEが594.1cpから531.3cp、pair accuracyが`0.6357`から`0.6471`へ改善した。ただし、これらは教師への近似であり、棋力向上の証拠ではない。さらに独立監査で、このrunは量子化ゲートへ進む前に事前登録契約へ違反していたと判明した。

保存された実行引数は`rank_weight=1.0`、`policy_weight=0.25`、`experiment_plan=''`だった。事前登録はrank / policy weightをともに0とし、実行を機械可読プランへ結び付ける契約だったため、一致していない。このデータにはrank / policy教師がなく、非0のweightが実際のlossへ寄与しなかった可能性はあるが、固定した実行契約への違反であることは変わらない。

加えて、curveとcheckpointにはepoch 0の`train_loss=NaN`、`val_sibling_pair_acc=NaN`、`val_sibling_top1=NaN`が記録されていた。「記録する全metricがfinite」という条件にも厳密に不合格である。したがって主判定は`preregistration-contract-invalid`であり、このcheckpointを有効な候補とは扱わない。

量子化誤差にも、独立再現できた二次的な不合格がある。最終監査で元のexact commandをsession logから復元すると、入力は均衡済みvalidation、`--verify-n 2968`だった。run rootに専用receipt fileはなかったが、保存済みartifactとこのexact commandから全2,968局面を再計算できた。

| 重み      |    mean absolute error |     max absolute error |
| --------- | ---------------------: | ---------------------: |
| base      |  `29.49924202633157cp` |  `209.0002596847653cp` |
| candidate | `25.497765624146755cp` | `229.96719146338023cp` |

candidate / base比はmeanが`0.8643532468185785`で改善した一方、maxは`1.1003201230957287`へ悪化した。mean側は通るが、事前登録したmax比上限`1.05`を超えるため、量子化ゲートは二次的にFAILである。先頭200局面で一度異なる値を得たのは、全件測定に対してprefixだけを比較した監査ミスだった。この独立再現は量子化FAILを確定するが、主判定である実行契約違反を救わない。

この無効なrunは再実行しない。後続のPyTorch・TorchScript・WASM parity検査とscreen 56局は実行していない。したがって、強くなったとも弱くなったとも対局からは判定できず、800,000局面への拡大、depth 16化、追加seed探索にも進んでいない。ライブ重みはSHA-256 `e4e738f99fbd8685bcfe2700e4df364af6274e75b44b298432fc313b9a3e28dc`のままで、本番変更は0である。
