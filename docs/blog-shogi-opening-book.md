## 1. 症状：同じ「変な手」を何度も指す

きっかけは作者の実戦報告だった。ハードモード（持ち時間約2秒）でこう進む：

```
▲７六歩 △８四歩 ▲２六歩 △８五歩 ▲７七角 △３四歩 ▲６六歩 △８四飛
```

8手目の**△８四飛**。飛車を一段浮かせる「浮き飛車」は、それ自体は立派な戦法だが、**この局面のこのタイミングでは早すぎる**。二段の作者から見て明確に感触が悪い。しかも別の相掛かりの将棋でも、似た筋の緩い手が出る。

まず、この手が本当に悪いのかを客観的に確かめた。プロ級エンジン**やねうら王**（depth24）にこの局面を採点させると：

- 最善は **△３三角**（後手視点 −23cp）
- **△８四飛は −126cp**。最善から**約100cp（歩1枚ぶん）劣り、候補手トップ6にも入らない**

作者の感覚は正しかった。AIは序盤で、計測可能なレベルの劣手を系統的に指していた。

## 2. 容疑者を消していく：推測で直さない

前作で骨身に染みた教訓——**症状から原因を推測すると外す。物証を取れ**——に従って、容疑者を1つずつ潰した。ここで2回、私（調査した本人）は間違えた。その過程も含めて書く。

**容疑者A：定跡ブックが悪い手を持っている？**
このAIには手書きの定跡ブックがあり、収録局面では定跡手を指す。「大きくした定跡に悪い手が混ざったのでは」と最初は疑った。——だが git 履歴を確認すると、**この定跡はやねうら王 depth18 で全手を検証済み（悪手ゼロ）**の方だった。推測は外れ。

**容疑者B：変化（variety）機構が緩い手を選んでいる？**
定跡には「人間らしく手を散らす」ために、最善から一定幅（ハードで140cp）以内の手を許容する仕組みがある。「この許容幅が浅い1手評価と組み合わさって緩い手を通しているのでは」——もっともらしい仮説だが、これも**実測で棄却**された。

**決定打は、実測ハーネス**だった。問題の局面を実際に定跡関数に問い合わせるテストを書いて走らせると：

```
[game A / hard] book returns: NULL (out of book → search)
```

**定跡はそもそも「この局面を知らない」と答えていた（NULL＝定跡外）**。つまり定跡もvariety機構も無罪。△８四飛は、定跡を外れた後の**探索（NNUE評価）が自力で選んだ手**だった。

## 3. 真犯人：NNUEの「序盤バイアス」

なぜNNUEは浮き飛車を選ぶのか。構造的な理由がある。

- **浮き飛車は駒損しない**。1手の駒得・駒損で見れば互角の手
- NNUEは局面を数値にする"目"だが、**学習データの大半は中盤〜終盤**。序盤の「形の良し悪し」——同じ駒割でも、この瞬間の飛車浮きは構想として緩い——という判断は、学習が薄い
- 探索を深くしても、**末端の評価が「ほぼ互角」と言う限り、その先の微差は掘り出せない**

つまりこれは前作の「sigmoid飽和」（終盤の病）と対になる、**序盤の病**だ。飽和は「大差の中の微差が潰れる」問題、こちらは「互角の中の構想の差が見えない」問題。どちらも、**探索ではなく評価（データ）の弱点**である。

## 4. 定跡はどう動いているか（仕組みの話）

対策の前に、定跡がどう引かれているかを正確に書いておく。誤解が多いところだ。

**検索は「局面ハッシュの表引き」**。定跡は「手順のリスト」ではなく、ビルド時に手順を盤上で再生して**局面ハッシュ（Zobristハッシュ）→ 候補手** のハッシュ表に変換してある。実行時は、現在の局面のハッシュで表を引くだけ（O(1)）。

この設計の重要な帰結が2つある：

- **手順前後（トランスポジション）には強い**。違う順序で指しても、**同じ局面に合流すればハッシュが一致してヒットする**。「手順が前後したら定跡が効かなくなる」ことはない
- **本当に知らない局面に来たら、即座に定跡外**。そのときは NULL を返して探索に切り替わる。「全く機能しなくなる」のではなく、AIの生の読みに戻る——ただしそこで §3 の序盤バイアスが顔を出す

つまり定跡の弱点は「引き方」ではなく、**カバーしている局面の数**そのものだ。

## 5. モグラ叩きの実録：1本足したら、1手先に逃げた

真犯人が「定跡の穴」だと分かったので、まず素直に穴を塞いだ。問題の角道相掛かりのライン（▲７六歩△８四歩▲２六歩△８五歩▲７七角△３四歩▲６六歩）に、やねうら王検証済みの **△３三角** を定跡追加。回帰テストも書いて「△８四飛が返らない」ことを機械的に保証した。

数時間後、作者から再報告が来た：

```
8. △３三角  ← 直した手。定跡が効いている
9. ▲２五歩
10. △８四飛  ← また出た
```

**修正は効いていた。しかし1手足りなかった。** 追加したラインは8手目まで。作者が▲２五歩と続けた瞬間、局面はまた定跡外に出て、NNUEが同じ浮き飛車を指した。やねうら王で確認すると、10手目の△８四飛も**−85cp**（最善△６二銀の−27cpから約58cp劣る）で、やはり劣手。

対処として、ラインを**18手目まで**延長し、9手目の別の自然手（▲７八金）への分岐も足した。10手目は△７四歩（エンジン最善）を返すようになり、回帰テストも通った。——だが、ここで認めざるを得なかった：

> **定跡を1本ずつ足すのはモグラ叩きだ。** 塞いだラインの1手先、あるいは隣の変化で、同じバイアスが必ず再発する。カバレッジを「線」でなく「面」にしない限り、この繰り返しは終わらない。

## 6. プロ用エンジンはどうしているか

ここで当然の疑問：**やねうら王のような本物のエンジンは、なぜ序盤で緩い手を指さないのか？**

答えは2段構えだ。

1. **定跡の規模が桁で違う**。公開されている定跡ファイル（やねうら王プロジェクトが配布している「標準定跡」「やねうら大定跡」など）は**数十万〜数百万局面**を収録している。主要な戦型なら序盤20〜30手は定跡内で、そもそも評価関数の出番がない
2. **評価関数も桁違いのデータで学習**しているので、定跡を外れても序盤が破綻しない

うちのAIは、定跡がコード直書きの**数十ライン規模**、NNUEも小型・少データ。**アプローチはプロと同じで、規模だけが小さい**。そして§5の実測が示した通り、この規模差はモグラ叩きでは埋まらない。

もう一つ収穫だったのは、**定跡データが公開資源として存在する**こと。やねうら王プロジェクトの定跡ファイルに加え、**floodgate**（コンピュータ将棋の対局サーバ）の棋譜アーカイブも公開されていて、強豪エンジン同士の序盤を大量に取れる。人力で1ラインずつ書く必要は、最初からなかった。

## 7. 転換：数十ラインから数千〜数万局面へ（進行中）

というわけで、方針を転換した。**定跡を「面」で作る**。

設計はこうだ：

- **データ源**：やねうら王プロジェクトの公開定跡を第一候補として変換（ライセンス確認込み）。不可なら、やねうら王を並列に走らせて自動生成（各局面で depth16〜18・最善から50cp以内の手だけ採用して木を展開）
- **配信方法**：巨大データをコードに直書きせず、**NNUEの重みと同じ「静的ファイル＋起動時fetch」方式**に。目標は gzip後1〜3MB・**5,000〜50,000局面**
- **品質ゲートは不変**：depth18 のサンプル検証で**悪手ゼロ**（最善から100cp超劣る手を入れない）。手書きの検証済みラインは残し、大規模定跡より**優先**して引く
- **フォールバック**：ファイルの取得に失敗しても、従来の手書き定跡だけで動く（劣化なし）
- **ハードは全部使う**：生成・検証は YaneuraOu を複数プロセス並列（10〜12スレッド）で回す

これが入ると、主要戦型は序盤20手前後まで定跡内になり、「緩い手の出番」自体が激減する。モグラ叩き（作者が踏んだ筋を後追いで塞ぐ）から、**最初から面でカバーする**体制への転換だ。

### 7.1 結果：5万局面の定跡が本番に載った

パイプラインは完成し、本番にデプロイされた。結果を数字で書く。

**データ源はやねうら王チームの「新ペタショック定跡」**（世界コンピュータ将棋選手権WCSC35で使われた、233万局面の定跡。**MITライセンスで公開**されており「研究などにご自由にお使いください」と明記——ライセンス確認はこの手の取り込みで最初にやるべき工程だ）。この233万局面から、初期局面に到達可能な序盤（20手以内）を幅優先で辿り、**49,961局面・171,512手**を抽出した。

**配信は静的ファイル844KB（gzip後535KB）**。NNUEの重みと同じく、コードには入れずページ起動時に非同期でfetchする（実測~86ms）。取得に失敗しても手書き定跡だけで従来通り動くので、劣化はゼロ。手書きの検証済みライン（△8四飛の回帰テストの根拠）は**局面単位で常に優先**して引く。

カバレッジはこう変わった：

| | before（手書き） | after（ペタショック取り込み） |
|---|---|---|
| 収録局面 | 数十ライン | **49,961局面** |
| 10手目の局面数 | 数個 | **約1,400** |
| 20手目の局面数 | — | **約5,100** |
| 実測の定跡在局時間 | 数手で外れる | **全難易度で17〜19手目まで定跡内**、変則手順でも13手目まで追随 |

体感も変わる。定跡内の手は**約0.5秒で即応**し（探索なら数秒）、序盤の「緩い手の出番」自体が消えた。

### 7.2 いちばん大事な発見：既製の定跡でも「盲信」はできなかった

ここが今回の山場だった。ペタショック定跡には評価値が付いているので、当初は「付属の評価値でフィルタすれば悪手ゼロにできる」と考えていた。**サンプル検証してみると、それでは足りなかった**——付属評価値だけで通した手のうち**約1.5%が、depth18で測ると最善から100cp超劣る**手だった。定跡の評価値は作られた時点のもので、浅い局面では今のエンジンの判断とズレる。

そこで方針を全数検証に切り替えた。**抽出した171,512手（剪定前176,941手）すべてをやねうら王depth18で採点し直し、最善から90cp超劣る5,429手を剪定**した。M4 Proで**12エンジン並列**（深さは削らず、並列で数を稼ぐ）にして約2.5時間。

さらにその全数検証の途中で、もう一つ罠を踏んだ。並列エンジンで置換表（TT）を共有したまま測ると、**同じ局面のdepth18スコアが実行のたびに最大150cpも揺れる**——これでは「90cp基準の剪定」自体が再現不能になる。対策として**毎探索前にTTを確保し直す決定的プロトコル**（同じ局面なら評価値もノード数も完全一致する測り方）を確立してから測定した。独立シードでの再検証（891局面・3,096手）で**100cp超の劣手は0件**を確認。

> 前作からの教訓「検証そのものが罠だらけ」は、定跡の取り込みでも例外ではなかった。**外部データの品質表示を信じず、自分のゲートで測り直す。測定器（エンジンの設定）の再現性まで疑う。**

## 8. で、どれだけ強くなったのか——正直な測定

5万局面の定跡が入って、めでたしめでたし——で終わらせず、**効果を数字で測った**。同一エンジン同士で、片側だけに大規模定跡を持たせた自己対戦を144局（持ち時間・開局条件を変えた3セット、先後入替、95%信頼区間つき）。

結果は、正直に書くと**「小さめのプラス。統計的には有意でない」**だった。

| 条件（48局ずつ） | 定跡あり側のスコア | Elo差（点推定） |
|---|---|---|
| 2秒/手・ランダム開局 | 54.2% | +29 |
| 2秒/手・定跡内開局 | 57.3% | +51 |
| 1秒/手・定跡内開局 | 51.0% | +7 |
| **合計144局** | **54.2%（95%CI 46.6〜61.7%）** | **+29（CIは0を跨ぐ）** |

点推定は+30〜50 Elo程度のプラスだが、95%信頼区間はゼロを跨ぐ。「+50 Eloを有意に検出するには約400局が要る」という規模の話で、この局数では「大きな効果は否定できる。小さな正の効果はありそう」までしか言えない。

**面白いのは「なぜ小さいか」の分析**のほうだ。ログを掘ると：

1. **自己対戦では、大規模定跡がほとんど発火しない。** 手書きの検証済み定跡が自己対戦の本線を17手までカバーしており、そこを一歩でも外れた局面は**両者とも**定跡外になる。5万局面という規模でも、1局あたりの「外部定跡由来の手」は平均1.3〜1.4手にとどまった。定跡は「相手が定跡形を指してくる間」しか働けない。
2. **「序盤で時間を貯めて中盤で深く読む」効果は、構造的に存在しなかった。** このエンジンの持ち時間は1手単位（ゲームクロックではない）ので、定跡で浮いた時間は繰り越されない。
3. だとすると、大規模定跡の真価は**自己対戦ではなく対人間**に出る。人間は定跡形を指してくるから、定跡の網に長く留まる。実際、作者（二段）の体感では序盤の質は明確に向上している——**「自己対戦の勝率」と「対人間の体感」が乖離する**のは、前作の「近似指標は対局の強さを予言しない」の変奏だ。測る土俵によって、同じ改善が違って見える。

> 教訓の追加：**改善の価値は、測る土俵に依存する。** 自己対戦で小さく見える定跡の効果は、定跡形を指す人間相手には大きく効く。逆もまた然り。「何に対して強くなりたいのか」を先に決めてから測ること。

## 9. 第4サイクル：定跡を30手まで伸ばし、序盤バイアスを「脳」ごと直す

§8の最後で「進行中」と書いた2つ——**定跡の30手深掘り＋変則手カバー（v2）**と、**NNUEの序盤バイアスを根治する再学習**——が両方とも本番に載った。この2つは、§8の「測る土俵によって同じ改善が違って見える」という話の、きれいな裏返しになっている。

### 9.1 定跡v2：5万 → 9.8万局面、そして「線」を「面」にする

まず定跡を作り直した。ねらいは2つ。

1. **深さ**：本線を20手級から**30手級**まで伸ばす（ply20全域＋ply21〜30の主要変化）。
2. **面のカバー**：人間が指してくる「定跡形からの自然な逸脱」に、定跡側の返し手を用意する。§5でやった「モグラ叩き」を、手作業ではなく**網羅生成**でやる。

②の逸脱カバーは、到達頻度の高い局面から1,200個を種にして、各局面で「300cp以内の自然な手のうち、定跡を外れる手」を洗い出し、その**一手先にやねうら王depth18の応手を1つずつ**足していく専用スクリプトを書いた。結果、**49,961 → 97,767局面**（gzip約1MB、2.5MB上限内）。自然な10例の変則手プローブは**6/10 → 10/10**に。

**作り直して初めて見つかった、v1の重大な穴**もあった。▲7六歩に対する△3四歩（最善との差わずか31cp＝ほぼ互角の本命手）が、生成時の「1局面あたり展開5手まで」というキャップに弾かれ、**振り飛車系のサブツリーが丸ごと欠落していた**。浅い手数では展開キャップを8に緩めて解消。「線は正しくても面に穴」という§の教訓が、自分の定跡自身から出てきた形だ。

悪手ゼロの担保は前回と同じ**決定的プロトコル**：全303,321手をdepth18で全数検証し、gap>90cpの手を剪定。再利用した5万局面分は、決定性ゲート（12局面のcp完全一致）を確認してから流用。独立シードでの再検証でもgap>100cpは0件だった。

### 9.2 NNUE追い焚き：△8四飛が「気持ち悪い」のは脳の問題だった

§3で突き止めたとおり、序盤の不自然な手（浮き飛車△8四飛など）の真因は定跡ではなく**評価関数（NNUE）の序盤バイアス**だった。定跡は「定跡形の間」しか効かない。定跡を外れた瞬間に変な手が出るなら、直すべきは**脳そのもの**だ。

そこで、序盤に厚い教師データで**追い焚き（再学習）**した。既存の資産を捨てず、序盤局面を約56万追加：本番の定跡（ペタショック由来）をBFSで展開したノードと、**「定跡を1手出た直後」の局面**（＝まさに変な手が出る場所）を中心に、やねうら王depth12で採点。混合後の学習データは約590万局面。

**採否は、近似指標ではなく実対局で決めた**。ここが§8との対比だ：

| 指標 | 追い焚き前 | 追い焚き後 |
|---|---|---|
| 序盤ホールドアウトのMAE | 214.7 | **175.6（−18%）** |
| 序盤ホールドアウトのpair精度 | 0.897 | **0.931（+3.4pt）** |
| 一般ホールドアウトのpair精度 | 0.9040 | 0.9001（**−0.4pt**、正直に言うと微減） |
| **自己対戦A/B（192局・先後入替）** | — | **61.7%勝ち越し（95%CI 54.7〜68.3%、p≈0.0006）** |

問題の局面での△8四飛は、静的評価の**15位から23位**へ沈み、浮き飛車系の手も一貫して順位を落とした。歩不成のような不自然な手が上位に来る局面も無くなった。

**そして§8といちばん違うのは、今回のA/Bは統計的に有意だった**こと。理由は明快で——**定跡はめったに発火しないが、評価関数は毎手働く**。§8で大規模定跡の自己対戦効果が小さく見えたのは、自己対戦だと両者すぐ定跡を外れて定跡が「出番なし」になるからだった。評価関数の改善にはその逃げ場がない。1局の全手に効くから、192局で下限が50%を明確に上回った。

> 教訓の追加：**「どこで効くか」が有意差を決める。** 全局面に効く変更（評価関数）は自己対戦で素直に有意になり、条件が揃ったときだけ効く変更（定跡）は対人間で真価が出る。同じ「強くする」でも、正しい測り方は改善の性質で変わる。

（両方とも独立検証——A/Bログの再集計、ホールドアウトの再走、ビット一致、テスト全数パス——を通してから本番反映。近似指標のpair精度は*採否の根拠にしていない*。前作の「近似指標は対局の強さを予言しない」を、今回も守った。）

## 10. 実験ノート：効かなかったこと（進行中）

強くなった話ばかり書くとフェアじゃない。実際の開発は**「効かなかった実験」の方が多い**。第4サイクルの後、さらに強くしようと2本の実験を並行で走らせた。片方は完全な行き止まり、もう片方も雲行きが怪しい。負けの記録こそ役に立つので、正直に残す。

### 10.1 終盤をもっと速く ―― 「もう終わっていた」行き止まり

実戦で終盤に読み抜けがあった（72手目の詰み見落とし）ことから、「終盤の探索が遅くて浅いのでは」と疑った。持ち駒が多い終盤は、打つ手（ドロップ）が爆発的に増える（盤上20手に対しドロップ160〜330手）。ここの手生成を速くすれば深く読める、という筋読みだ。

プロファイルすると、確かに終盤の1ノードのコストの大半は**手生成と合法性チェック**（合わせて約99%、評価はわずか1%）で、その主犯はドロップ手の量的爆発だった。ビットボードで空きマスと合法な打ち場所を一括計算すれば速くなる。

**ところが調べると、その最適化は既に終わっていた。** 少し前のサイクルで、まさに同じビット演算による高速化がJS・WASM両方の探索に入っていた（合法性チェックの省略、ドロップ生成の1パス前計算）。ビット完全一致を保ったまま追加で削れる余地は、もう残っていなかった。

さらに間抜けなことに、**最初の「遅い」という診断そのものが的外れ**だった。あの27〜41µs/ノードという数字は**JSエンジン基準**で測ったもの。本番はWASMエンジン（JS比15〜30倍速）で動いていて、そこで測り直すと終盤の1ノードは約2.76µs、しかもコストの支配項は**手生成ではなくNNUEの葉評価**に入れ替わっていた。要するに「遅い場所」を間違った物差しで見ていた。

> 教訓の追加：**本番で走っている経路そのものを測れ。** 代理のエンジン（測りやすいJS版）で出したプロファイルは、最適化済み・別実装の本番（WASM版）には当てはまらない。「どこが遅いか」は実装が変われば入れ替わる。—— これは前作の「測定器そのものを疑え」の、経路版だ。

収穫がゼロだったわけではない。**本番WASM経路で終盤のスループットと到達深さを正しく測るベンチマーク**を残せたし、「次に終盤を速くするならホットパスは手生成ではなくNNUE評価だ」と数字で分かった。つまり終盤を強くする道も、結局は**評価関数（脳）を良く/速くする**方に戻ってくる。

### 10.2 KP特徴量 ―― 「賢い入力」は勝てなかった（A/B確定待ち）

もう1本は、NNUEの**入力の作り方**を変える実験。今の脳は盤面を「どのマスに何の駒があるか」でそのまま入力している。プロの評価関数の定番は**KP（King-Piece）**という、**自玉の位置を基準に駒の配置をエンコード**する方式で、玉の安全度を捉えやすく、一般に大きく強くなると言われる。これを試した（自玉の位置を6バケットに分け、バケットごとに別テーブルを持つ「factored KP」）。

学習は問題なく回り、**ブラウザ推論（WASM）にKP版を載せる配線もできた**（心配していた「推論が対応していない」壁は無かった。バケット別テーブルの選択までWASMで動く）。ここまでは順調。

問題は肝心の強さだ。現本番（board特徴のrunOp1）との自己対戦A/Bで、**KP版は60局で20勝40敗＝勝率33.3%（Wilson 95%信頼区間 23〜46%）**。信頼区間の上端すら50%に届かない ―― つまり**統計的に明確に弱い**。学習時の一致率もKP版0.911 < board版0.916 とわずかに劣っており、実対局でもはっきり負けた。**採用しない。**

> 教訓：**「理論的に賢い入力」が「素朴な入力」に負けることがある。** 第2サイクルでも、凝った損失関数はデータが少ないうちだけ効いて、データが十分になると素朴な回帰に抜かれた。今回のKPも同じで、賢い構造は、それを活かすだけのデータ量・学習量が揃って初めて効くのかもしれない（今回の590万局面・この規模の学習では活かしきれなかった）。KPが「悪い」わけではなく、「今のこの構成では勝てなかった」というだけ。負けは負けとして記録し、素直に board 特徴の現行版を本番に残す。

### 10.3 次に試していること（進行中）

KPが負け、終盤高速化も行き止まりだった後、では次のレバーは何か。終盤の一件で分かった「**本番のホットパスはNNUE評価**」という事実が、そのまま2つの方針を指している。

- **評価を速くする（SIMD化）**：WASMのSIMD128命令でNNUE推論をベクトル化する。速くなれば同じ持ち時間で探索が深くなり、全局面に効く。「賢さ」ではなく「速さ」なので、KPのように学習が外す心配がない確実性の高い筋。
- **自己対戦データで学習する**：教師局面を、ランダムなロールアウトではなく**エンジンが実際に到達する局面**から採る。分布が実戦に近づく。当初考えていた「単にデータを1000万まで増やす」案は、過去の実績（大きく伸びたのは100万→500万の段階）から逓減が濃厚だったので取り下げ、**同じ“データを足す”でも質（分布）で効かせる**この方向に切り替えた。

どちらも結果が出たら、勝ったにせよ負けたにせよ、この実験ノートに追記する。

## この章の教訓

- **「検証済みの定跡」と「十分な定跡」は別物**。1手ずつは正しくても、カバレッジが線だと穴から漏れる
- **修正の検証は「その局面」でなく「その筋の続き」まで**。1手直して満足すると、問題は1手先に逃げる（実体験）
- **評価関数の弱点は、終盤（飽和）と序盤（構想）の両端に出る**。中盤が強いのは、学習データが中盤に厚いから
- **公開資源を探すのを最初にやるべきだった**。車輪の再発明（手書き定跡）は、規模の壁に当たる
- **外部データの品質表示を盲信しない**。付属評価値だけでは1.5%の劣手が漏れた。自分のゲート（depth18全数検証）で測り直して初めて「悪手ゼロ」と言える
- **測定器の再現性まで疑う**。共有TTのままでは同じ局面のスコアが150cp揺れ、剪定基準そのものが崩れる。決定的に測れる状態を先に作る
- **フォールバックを最初に設計する**。定跡ファイルの取得失敗＝手書き定跡で従来動作、という退路があるから、大きな変更を安心して本番に出せる
- **「どこで効くか」が有意差を決める**。毎手働く評価関数の改善は自己対戦で素直に有意になり、条件が揃ったときだけ効く定跡は対人間で真価が出る。同じ「強くする」でも正しい測り方は変わる（第4サイクル）
- **変な手は、定跡でなく脳を疑う**。定跡を外れた瞬間の悪手は、序盤に厚い教師での追い焚きで根治する。近似指標（pair精度）は採否の根拠にせず、最後は192局の実対局で決めた
