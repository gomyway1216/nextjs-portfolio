# みんなの大喜利王

## 遊び方

- 開始ページ: `/games/ogiri`。Gamesのパーティーカードから開けます。
- 主催者・参加者: `/games/ogiri/ABC234`。コードは例です。
- テレビ: `/games/ogiri/ABC234/tv`。このURLにホストの秘密情報はありません。
- 主催者がスマホでルーム作成→「テレビ画面を開く」のURLをPCで開く→HDMIまたはChromeのキャストでテレビへ。テレビ内蔵ブラウザでも表示できます。TV用タブは表示したままにしてください。非表示タブの同期は止まります。
- QRを読み取った各自が名前とアバターで参加。回答者3〜12人、アカウント・アプリ不要。主催者は標準で進行専用、TVは表示専用で、どちらも回答者の人数・投票・順位に含みません。主催者自身も遊ぶ場合はスマホで別参加するか、作成時/開始前に「この端末でも回答に参加する」を選べます。旧ルームの参加者ホストは引き継ぎ、開始前に切り替え可能です。各お題に2人が回答し残りが投票するため、投票者2人以上には回答者4人以上が必要です。
- 2問を送信した後に「これでOK！」で確定します。全員が確定すると自動進行ONでは投票へ、OFFでは主催者の操作を待ちます。回答タイマーは目安で、0秒になっても回答・修正・確定を続けられます。未回答者がいるまま自動で締め切りません。主催者は「次へ進む」の確認後に締め切れます。確定前に未送信の変更があれば先に更新が必要です。「回答を直す」で確定を取り消せます。確定・取り消しは1回あたり既存ルームへの1操作で、追加のpollやコレクションはありません。
- 受付画面には人数に応じた配分を表示します。回答者N人なら1ラウンドNお題・全員2回答・各お題N−2人が投票し、各自もN−2回投票します。進行専用の主催者とTVを除き、途中退出がなければ全員の回答/投票機会が同じです。
- 新規ルームの標準は3ラウンド、回答の目安180秒・投票45秒・結果15秒・中間順位20秒。受付中は回答の目安を30〜600秒、投票を10〜120秒に変更できます。進行中も主催者は回答タイマーを60秒、投票・結果・中間順位の表示時間を30秒ずつ延長でき、一時停止にも対応します。既存ルームの回答・投票の保存済み設定は保持します。プレイ時間は人数と回答/投票の速さで変わります。ハロウィン専用テーマ・お題に切り替えできます。
- 1ラウンドのお題数は回答者の人数と同じで、各自の回答は2問。自分の対戦は投票できません。1票100点、勝利200点、同点は勝利ボーナスなし。未回答・非表示は0点。順位も同点を保持します。
- ゲーム内の得点とは別に、同じルームのパーティー通算ポイントを保持します。終了順位1位10pt・2位7pt・3位5pt・その他3pt、同順位は同点。再戦でゲーム内得点だけをリセットし、通算は残します。将来の別ゲームにも同じ順位換算を使える共通関数 `src/lib/party/points.ts` を利用します。現在の対象は大喜利で、別ルームや既存クイズ等とは未接続です。結果発表済みの対戦がない途中終了は通算対象外、導入前の既に保存済みの結果は遡って加算しません。
- 中間・最終発表では「このゲーム」と「パーティー総合」を切り替えられ、中間の通算表示は暫定です。ラウンドMVP・追い上げ・最多得票の一言をタップすると大きく発表します。未発表・非表示・退出処理済みプレイヤーの回答は含みません。同票の回答は先に発表したものを代表表示します。
- 通算の加算・終了済み印・履歴を同じ条件付き保存で確定し、二重終了や再送で追加加算しません。追加のFirestore読み書きや別のpollはありません。90日履歴とダウンロードにも、そのゲーム終了時点の通算を残します。ルーム失効後の確認は履歴リンクから行います。
- 今回のお題が割り当てられていない不参加者には通算を加算せず、過去に獲得した通算は保持します。割り当て済みの参加者は途中切断・未回答でも対象です。中間の暫定表示も同じ判定を使います。
- 新規の途中参加は再戦まで待機。参加済みの端末は更新・切断後も同じブラウザのCookieで復帰します。1ルームの累積参加履歴は64人までです。別端末へのホスト移譲はありません。
- 「過去のゲーム」(`/games/ogiri/history`)からお題・回答・票数・得点・最終順位を閲覧できます。結果発表済みの対戦を終了時に保存し、再戦やルーム失効後も終了から90日間残ります。「結果をダウンロード」はオフラインで読めるUTF-8テキストです。未発表・非表示の回答は公開しません。導入前に上書き・削除された過去ラウンドは復元できません。
- 履歴一覧はこのブラウザが受け取ったリンクを端末内に最大100件保持します（ルームから再取得できる参照は直近50ゲーム）。ブラウザのデータ削除や別端末では履歴リンクが必要です。リンクを知る人が閲覧できるため参加者だけに共有してください。通常の6文字のルームコードだけでは、失効済みルームの履歴を検索できません。
- 20種類のオリジナル画像キャラクターから選べます。選択・参加・待機・得点・優勝時の動きがあり、動きの軽減とOS設定に対応します。画像は背景透過WebP、20枚合計約490KiB。生成時の情報は `docs/ogiri-character-prompts.json` に記録し、ゲーム中の画像生成APIはありません。既存12種類の識別子と画像は維持し、既存セッションと保存済み履歴のキャラクターも画像で表示します。
- 音は最初はミュート。ナビの黄色い「音OFF」や、主催者/TV待機画面の「音を出して試す」を押すと有効になります。「音設定」で10種類（選択・参加・開始・回答送信・投票・投票開始・結果発表・中間順位・優勝・残り5秒）を個別に試聴できます。初期音量60%、音量調整付き。テレビで鳴らす場合はテレビ側の画面でクリックし、音が重ならないようスマホはオフがおすすめです。ブラウザの再生再開が完了したことを確かめてからON表示し、中断時は「音を再開」でユーザーの操作から復帰します。サイン波と三角波の和音・低音を使うオリジナル合成音で、音の立ち上がり直後に小さくなりすぎない包絡線にしています。ブラウザ内で合成し、音声ファイル取得や外部生成APIはありません。非表示時/ミュート時は再生中の音を止め、画面を閉じるとAudioContextを解放します。再読込直後の結果や同じ状態のpollでは発表音を繰り返しません。BGMはありません。
- 効果音のオフライン試聴ファイルは `npx tsx scripts/ogiri/render-sounds.ts` で `.artifacts/ogiri/sounds/` に再現できます（ゲームと同じ音符・音量・包絡線）。

## 実装と既存機能との分離

調査結果: Next.js 16.4 / App Router、React 19、Firebase Admin SDK、FirestoreとRealtime Database、Firebaseゲスト認証、QR生成、Vitest、Playwright、Vercel/GitHub Actionsが既存。既存対戦ゲームはRTDB `gameRooms`、メダル・ランキングは別領域です。

本ゲームは既存のFirestore Admin SDKを再利用し、`ogiri_party_rooms/{code}` に専用の部屋を保存します。既存ゲームの緩い共有RTDB書き込みモデルをそのまま流用すると未公開回答を守れないため、ゲーム操作はすべてNext.js API経由にしました。

- ゲストに256ビットのランダム秘密を発行。DBにはSHA-256ハッシュのみ。ルームごとのHttpOnly / SameSite=Strict Cookie、HTTPSではSecure。参加者が送ったID・権限・得点は採用しません。
- Firestoreの更新時刻を条件にする原子的な更新で参加・回答・投票・得点・進行を直列化（競合時は最新データを再読込し権限・期限から再検証）。部屋コードは暗号学的乱数とcreate-if-absentで衝突を処理。ホストの次へ操作はフェーズ識別子を検証し再送で飛ばしません。
- 公開応答は明示的な項目リストから組み立てます。回答中は本人の2問だけ、投票時は現在の2回答だけ、投票結果で初めて作者名を公開。TV指定は同じブラウザでも参加セッションを使いません。
- クライアントはゲーム進行中は応答完了後1.5秒間隔で同期。非表示タブとオフライン中は取得・ハートビートを停止し、復帰時に直ちに再取得します。待機・一時停止・終了画面、自動進行をオフにした結果発表・中間順位、回答の目安時間後で状態が変わらない場合は15秒後に5秒間隔、1分後に15秒間隔、15分後に完全休止し「再接続する」を表示します。回答の目安時間後は新しい期限や書き込みを繰り返さず、通常の取得だけで待ちます。手動の結果画面はカウントダウンと秒読み音を表示せず、主催者の「次へ進む」で進行・同期を再開します。TVも長時間休止後は再接続が必要です。期限切れ・存在しない部屋への取得は終了し、一時的な通信エラーは最大30秒間隔で再試行、15分変化がなければ休止します。投票の締め切りと自動の結果表示時間はサーバー時刻。期限到達を検知したAPIがサーバー側で次の状態を確定するためホストの短時間の切断中もテレビ/他の参加者で進行します。回答中は全員の確定か主催者を待ち、全画面を閉じても勝手に進みません。
- 同一ラウンドでランダムな巡回ペアを使い、奇数・偶数とも各自2人の異なる相手と対戦。過去の対戦回数が少ない巡回を選択します。出題はゲーム内重複なし、再戦にも履歴を引き継ぎ（選択ジャンルが不足する場合に再戦時リセット）、隣接ジャンルを分散。
- 100文字まで、NFKC・制御文字除去、JSONリクエスト4KiB上限、Origin検証、操作別IPレート制限。テキストはReactでエスケープ。レート制限は既存のインスタンス内方式であり、分散した大規模攻撃に対する全体上限ではありません。
- 最後のゲーム操作から8時間でAPIアクセス不可。Firestore TTL `deleteAfter` によって削除。TTL削除は即時ではなく通常24時間以内。本人の端末の下書きは送信時に削除します。
- 履歴は専用の `ogiri_party_history/{128-bit random id}` に1ゲーム1文書を作成。ルーム更新の条件付きバッチと同時に確定し、再送・同時終了でも二重保存や再戦による上書きを防ぎます。本文は公開項目だけのJSON文字列で、秘密情報・投票者ごとの選択は含みません。進行中の通常APIには参照だけを載せ、履歴本文は配信しません。終了後の保存文書は変更しません。
- 履歴一覧はDB検索なし、詳細は開いたとき1文書だけ取得、pollなし。同じ端末の再閲覧には最大1時間のprivateブラウザキャッシュを使用。ダウンロードは取得済みデータから生成し追加通信なし。90日経過時点でAPI閲覧を止め、TTLで文書を自動削除します。専用コレクションのインデックスを無効化し、本文の索引ストレージを節約します。
- Firebaseルールの変更は不要。既存の本番Firestoreルールは一般利用者の直接読み書きを拒否し、管理者のみ許可します。既存RTDBルール、メダル、ランキング、ログインは変更しません。

## 検証方法

```sh
npm test -- tests/unit/ogiri tests/unit/gameCoverAssets.test.ts tests/unit/locales/gameCatalogStrings.test.ts
npm run build
npx --yes firebase-tools@15.34.1 emulators:exec --project demo-ogiri --config tests/ogiri/firebase.json --only firestore 'npx playwright test --config playwright.ogiri.config.ts'
```

エミュレーター利用は `OGIRI_EMULATOR=1` と `FIRESTORE_EMULATOR_HOST` の両方が必要。Vercelでは選択できません。実際のFirestoreエミュレーターとHTTP APIを使い、各参加者は独立したCookieを持つブラウザコンテキストです。インメモリの偽サーバーへの差し替えはありません。CIはChromium/WebKitで10人・12人+テレビを開始→回答→全対戦投票→結果→再戦まで操作します。

実機のiPhone/Android、HDMI、Castの物理接続、Wi-Fiからセルラーへの実回線切替は別途当日の確認が必要です。自動テストはモバイル幅・ブラウザオフライン切替・ページ更新で代替しています。

## 運用

本番は既存VercelのmainデプロイとFirebaseサービスアカウント設定を使用。新しい有料サービスや外部生成APIは不要です。同期はWebSocketではなくHTTPポーリングなので、Firestore読み取りとVercel呼び出しは発生します（全画面が表示されゲームが進行し続ける10人+TV、20分の単純計算で約8,800回の取得と操作分。実際の間隔には応答時間も加わります）。放置した待機画面は1画面あたり15分間に100回未満の取得で休止するため、同じ15分を1.5秒固定で取得する場合の600回以上から削減します。ブラウザ側の停止は通常利用時の節約であり、直接APIを叩く攻撃の費用上限ではありません。IP制限はインスタンス内であり分散環境の全体上限ではなく、請求アラートやVercel Spend Managementなどの運用設定は別途必要です。

TTLの設定（当該コレクションだけに適用）:

```sh
gcloud firestore fields ttls update deleteAfter --collection-group=ogiri_party_rooms --enable-ttl --project=yudai-portfolio
gcloud firestore fields ttls update deleteAfter --collection-group=ogiri_party_history --enable-ttl --project=yudai-portfolio
gcloud firestore indexes fields update '*' --collection-group=ogiri_party_history --disable-indexes --project=yudai-portfolio
```

ゲーム設計・秘密情報の投影・公平なペア割り当ては独立した小さいモジュール。将来ゲーム用の汎用フレームワークは導入していません。

表示用フォントは [Dela Gothic One](https://github.com/google/fonts/tree/main/ofl/delagothicone) を固定UI文字とASCIIに絞ったWOFF2（54,444バイト）です。OFLは `public/fonts/ogiri-display-OFL.txt` に同梱。回答文・任意のプレイヤー名は端末の日本語フォントで表示し、外部フォントAPIを呼びません。吹き出しはHTML/CSSで描画し、登場・得点の動きは1回のみ。動きの軽減設定では停止します。
