# みんなのパーティー

## 遊び方

- 開始ページ: `/games/ogiri`。Gamesの「みんなのパーティー」から開けます。大喜利・みんなの多数決・だれのひとこと？・おえかき伝言便の4種類を選んで主催でき、終了後は同じルームでゲームを切り替えて再戦できます。
- 主催者・参加者: `/games/ogiri/ABC234`。コードは例です。
- テレビ: `/games/ogiri/ABC234/tv`。このURLにホストの秘密情報はありません。
- 主催者がスマホでルーム作成→「テレビ画面を開く」のURLをPCで開く→HDMIまたはChromeのキャストでテレビへ。テレビ内蔵ブラウザでも表示できます。TV用タブは表示したままにしてください。非表示タブの同期は止まります。
- QRを読み取った各自が名前とアバターで参加。回答者3〜12人、アカウント・アプリ不要。主催者は標準で進行専用、TVは表示専用で、どちらも回答者の人数・投票・順位に含みません。主催者自身も遊ぶ場合はスマホで別参加するか、作成時/開始前に「この端末でも回答に参加する」を選べます。旧ルームの参加者ホストは引き継ぎ、開始前に切り替え可能です。大喜利は各お題に2人が回答し残りが投票するため、投票者2人以上には回答者4人以上が必要です。
- 大喜利では2問を送信した後に「これでOK！」で確定します。全員が確定すると自動進行ONでは投票へ、OFFでは主催者の操作を待ちます。回答タイマーは目安で、0秒になっても回答・修正・確定を続けられます。未回答者がいるまま自動で締め切りません。主催者は「次へ進む」の確認後に締め切れます。確定前に未送信の変更があれば先に更新が必要です。「回答を直す」で確定を取り消せます。確定・取り消しは1回あたり既存ルームへの1操作で、追加のpollやコレクションはありません。
- 受付画面には人数に応じた配分を表示します。回答者N人なら1ラウンドNお題・全員2回答・各お題N−2人が投票し、各自もN−2回投票します。進行専用の主催者とTVを除き、途中退出がなければ全員の回答/投票機会が同じです。
- 新規ルームの標準は3ラウンド、回答の目安180秒・投票45秒・結果15秒・中間順位20秒。受付中は回答の目安を30〜600秒、投票を10〜120秒に変更できます。進行中も主催者は回答タイマーを60秒、投票・結果・中間順位の表示時間を30秒ずつ延長でき、一時停止にも対応します。既存ルームの回答・投票の保存済み設定は保持します。プレイ時間は人数と回答/投票の速さで変わります。ハロウィン専用テーマ・お題に切り替えできます。
- 1ラウンドのお題数は回答者の人数と同じで、各自の回答は2問。自分の対戦は投票できません。1票100点、勝利200点、同点は勝利ボーナスなし。未回答・非表示は0点。順位も同点を保持します。
- ゲーム内の得点とは別に、同じルームのパーティー通算ポイントを保持します。終了順位1位10pt・2位7pt・3位5pt・その他3pt、同順位は同点。再戦でゲーム内得点だけをリセットし、通算は残します。将来の別ゲームにも同じ順位換算を使える共通関数 `src/lib/party/points.ts` を利用します。対象はこのルームの大喜利・多数決・作者当て・絵の伝言で、別ルームや既存クイズ等とは未接続です。結果発表済みの対戦がない途中終了は通算対象外、導入前の既に保存済みの結果は遡って加算しません。
- 中間・最終発表では「このゲーム」と「パーティー総合」を切り替えられ、中間の通算表示は暫定です。ラウンドMVP・追い上げ・最多得票の一言をタップすると大きく発表します。未発表・非表示・退出処理済みプレイヤーの回答は含みません。同票の回答は先に発表したものを代表表示します。
- 通算の加算・終了済み印・履歴を同じ条件付き保存で確定し、二重終了や再送で追加加算しません。追加のFirestore読み書きや別のpollはありません。90日履歴とダウンロードにも、そのゲーム終了時点の通算を残します。ルーム失効後の確認は履歴リンクから行います。
- 今回のお題が割り当てられていない不参加者には通算を加算せず、過去に獲得した通算は保持します。割り当て済みの参加者は途中切断・未回答でも対象です。中間の暫定表示も同じ判定を使います。
- 「みんなの多数決」は全員が同じ選択肢から1つ選び、最多票の側に100点。同率最多は全て得点、無投票は0点です。1ラウンド1問、全員の投票または締切で発表します。
- 「だれのひとこと？」は全員が同じお題に1回答を送って「これでOK！」で確定。匿名の回答を1つずつ表示し、作者以外が名前とキャラから作者を当てます。正解100点、作者は外された票1つにつき50点。回答の目安時間を過ぎても確定を待ち、自動進行OFFなら主催者が進めます。
- 多数決・作者当てのお題は各36問、絵の伝言は48問の独自文です。進行専用ホスト・TV・再戦・通算・90日履歴を共有します。絵の伝言以外では設定したラウンド数を使います。未発表の回答や作者、投票者別の選択は公開しません。終了後に次のゲームを設定しても、終了済みのゲーム種別や履歴は変わりません。
- 「おえかき伝言便」は3〜12人で1ゲーム1回の同時伝言バッチです。各自に別のお題を配り、全員が「絵→言葉→絵」（3人）または「絵→言葉→絵→言葉」（4〜12人）を交代します。各チェーンで同じ人が二度担当せず、全員の描画・推測回数をそろえます。各手は送信後の「これでOK！」を待ち、目安時間後も修正できます。主催者の明示締切は未提出をパスにします。退出して戻った人は元の巡回の現在の担当へ戻ります。前の伝言がパスなら想像で続けられます。
- 描画は指・マウス、5色のペン、3段階の太さ、消しゴム、戻す・クリアを使えます。端末に下書きを保持し、送信中・確定後は編集を止めます。全チェーンをTVで順番に公開した後、好きな絵を拡大して一票（自作不可）。1票100点を描いた人に加算し、同順位のパーティー通算は同点です。絵・言葉・票数・得点は90日履歴とオフラインHTMLに残ります。
- 終了後の主催者画面に「次、なにやる？」と4ゲームの画像カードを表示します。カードを選ぶと、そのゲームの受付へ同じルームのまま移り、「設定を保存」は不要です。準備ができたら「ゲーム開始」で始めます。名前・キャラ・合言葉・休憩状態・パーティー通算と過去の履歴を引き継ぎます。選択と再戦受付への移行は1回の更新で確定し、TV・参加者の画面には操作ボタンを出しません。
- 新規の途中参加は再戦まで待機。「休憩する」でゲーム参加を休み、「参加に戻る」で再開できます。名前・キャラ・参加者ID・このゲームの得点・パーティー通算を保持し、自動ハートビートやページの再読み込みでは休憩を解除しません。割り当て済みの回答は復帰後に続けられ、休憩中に開始したラウンドの割り当ては途中追加せず次のラウンド・ゲームから参加します。休憩中も12人の参加枠を予約し、空きを作るために古い参加者を削除しません。主催者は休憩中も進行権限を保ちます。1ルームの累積参加履歴は64人までです。
- ページを閉じても、同じブラウザのCookie（発行から最大24時間）が残っていれば同じ参加者に戻れます。別端末・別ブラウザ・Cookie消去後は、「同じ参加者で戻る」で復帰方法を選びます。事前に設定した合言葉なら「ルームコード＋現在のニックネーム＋合言葉」、復帰コードなら「ルームコード＋自動発行の8文字」を入力します。名前だけで既存の参加者を引き継ぐことはできません。復帰は同じ部屋が有効な間の機能で、別の部屋で使う永続アカウントではありません。部屋は最後のゲーム操作から8時間で失効し、その後は復帰コードでも戻れません。終了済みの履歴は別に90日間保存します。
- 合言葉は本人の参加者画面「自分で決めた合言葉で戻る」で設定・変更します。6〜64文字、日本語と絵文字も使用でき、UnicodeはNFCで正規化します。同じルームの4ゲームで共通です。DBにはランダム16バイトsaltとscryptの検証値だけを保存し、入力そのものはCookie・sessionStorage・localStorage・URL・履歴へ保存しません。OWASPのN=2^15/r=8/p=3（32MiB）を使用し、設定・ログインの明示操作時だけ非同期で計算します。普段のpollには追加の取得・ハッシュ計算を増やしません。本人にだけ設定済みかを表示し、TV・未認証の画面へ検証値を出しません。変更後は古い合言葉が使えず、照合中に変更・退出処分されたログインも再検証して拒否します。存在しないニックネーム・合言葉未設定の場合もダミーのscrypt照合を行い、設定有無で早く終了する経路を作りません。入力欄はUTF-16の128単位まで受け付け、NFC正規化後のUnicode文字数を表示して6〜64文字だけ保存できるようにし、64個の絵文字も扱います。
- 復帰コードは本人の「別の端末で戻るための復帰コード」から確認・コピーします。初回発行と本人の再発行時だけ応答に載せ、通常の同期・TV・公開状態・履歴には含めません。DBには部屋に結びつけたSHA-256ハッシュのみを保存します。画面遷移・再読み込み用のコピーはそのタブのsessionStorageとメモリーだけに保持し、URL・localStorage・ログには保存しません。保存やクリップボードが使えない場合も操作は続けられ、コードを手で控えるか本人のセッションから再発行できます。導入前の部屋は本人の操作時に発行でき、再発行すると古いコードは失効します。
- 合言葉または復帰コードを使うと256ビットのセッション秘密を交換し、以前の端末・タブのセッションを無効にします。参加者ID・得点・休憩状態・主催者権限は保持します。主催者の復帰は同じ主催者としての端末切り替えで、別の参加者への権限移譲ではありません。コードを知る人は本人として戻れるため、主催者を含めコードを他の人に見せないでください。主催者に退出させられた人は元のコードでは復帰できません。復帰・再発行はIPごと毎分24回（同じWi-Fiの12人が各1回復帰し、各1回再試行できる回数）に制限し、復帰試行は既存のルーム文書の条件付き更新で5分間30回までに制限するため、インスタンス再起動・並列試行でも部屋単位の上限を維持します。失敗した試行は部屋の有効期間を延長しません。
- 「過去のゲーム」(`/games/ogiri/history`)からお題・回答・票数・得点・最終順位を閲覧できます。結果発表済みの対戦を終了時に保存し、再戦やルーム失効後も終了から90日間残ります。「結果をダウンロード」はオフラインで読めるUTF-8テキスト、絵の伝言は絵を埋め込んだ静的HTMLです。未発表・非表示の回答は公開しません。導入前に上書き・削除された過去ラウンドは復元できません。
- 履歴一覧はこのブラウザが受け取ったリンクを端末内に最大100件保持します（ルームから再取得できる参照は直近50ゲーム）。ブラウザのデータ削除や別端末では履歴リンクが必要です。リンクを知る人が閲覧できるため参加者だけに共有してください。通常の6文字のルームコードだけでは、失効済みルームの履歴を検索できません。
- 20種類のオリジナル画像キャラクターから選べます。選択・参加・待機・得点・優勝時の動きがあり、動きの軽減とOS設定に対応します。画像は背景透過WebP、20枚合計約490KiB。生成時の情報は `docs/ogiri-character-prompts.json` に記録し、ゲーム中の画像生成APIはありません。既存12種類の識別子と画像は維持し、既存セッションと保存済み履歴のキャラクターも画像で表示します。
- 音は最初はミュート。ナビの「音OFF」や主催者/TVの「音を出して試す」で有効になります。「音設定」で実際に使う10種類を試聴できます。回答登場は約0.6秒の録音された口ポップ、得点は即時の打音から約1秒でYayへつながる約2.8秒、順位は約3.7秒の演奏、優勝はグループYayと実際の拍手を重ねた約4.8秒です。得点が実際に増えた発表だけで得点の声を鳴らし、0点や答えを見せるだけの発表はポップにします。[出典とCC0の確認・加工内容](ogiri-audio-sources.md)を記録しています。5ファイル合計約123KBで、音を有効にした際に一度読み込み・デコードし、得点表示前のレイアウト処理で即再生します。残りの短音は独自Web Audio合成です。初期音量60%、100%時の旧32%制限を除去し、コンプレッサーとピーク上限0.96で調整。音量はこの端末に保存します。「閉じる」・Escape・パネル外操作で音設定を閉じられます。テレビで鳴らす場合はテレビ側の画面でクリックし、音が重ならないようスマホはオフがおすすめです。ブラウザの再生再開を確認してからON表示し、中断時は「音を再開」で操作から復帰します。非表示/ミュート時は再生中の音を止め、画面を閉じるとAudioContextを解放します。同じ状態のpollでは発表音を繰り返しません。回答・投票中は小さなBGMをループし、結果・順位・一時停止では停止します。「音設定」の「回答・投票中にBGM」で個別にOFFにでき、その選択は端末へ保存されます。[BGMの出典と検証](ogiri-waiting-music.md)を記録しています。
- 発表された加点と中間・最終順位の数字は約1秒でカウントアップします。順位の合計は今回の獲得分だけ増える見せ方で、サーバーの得点や順位は確定済みの値を使います。動きの軽減設定では最終値を即表示し、カウントのための通信や得点更新はありません。
- 投票中と結果発表中は、参加者（進行専用の主催者を含む）がスマホの😂👏🤯を連打でき、TVに浮かぶ絵文字と合計数で表示します。全4ゲーム共通で、匿名・表示専用です。得点・順位・パーティー通算・履歴には一切含めず、お題/画面が変わると0に戻ります。タップは端末で数えて最初の1回は約0.3秒後、以降は3秒に1回までまとめて送ります。TVは前回のpollからの増加分だけ（1種類につき最大8個）浮かべ、再読み込みや途中で開いたTVでは過去分を再生しません。動きの軽減設定では浮かぶ演出とスマホのポップを止め、合計数だけ表示します。
- 効果音のオフライン試聴ファイルは `npx tsx scripts/ogiri/render-sounds.ts` で `.artifacts/ogiri/sounds/` に再現できます（録音素材の変換にはffmpegを使用）。

## 実装と既存機能との分離

調査結果: Next.js 16.4 / App Router、React 19、Firebase Admin SDK、FirestoreとRealtime Database、Firebaseゲスト認証、QR生成、Vitest、Playwright、Vercel/GitHub Actionsが既存。既存対戦ゲームはRTDB `gameRooms`、メダル・ランキングは別領域です。

本ゲームは既存のFirestore Admin SDKを再利用し、`ogiri_party_rooms/{code}` に専用の部屋を保存します。既存ゲームの緩い共有RTDB書き込みモデルをそのまま流用すると未公開回答を守れないため、ゲーム操作はすべてNext.js API経由にしました。

- ゲストに256ビットのランダム秘密を発行。DBにはSHA-256ハッシュのみ。ルームごとのHttpOnly / SameSite=Strict Cookie、HTTPSではSecure。参加者が送ったID・権限・得点は採用しません。
- Firestoreの更新時刻を条件にする原子的な更新で参加・回答・投票・得点・進行を直列化（競合時は最新データを再読込し権限・期限から再検証）。部屋コードは暗号学的乱数とcreate-if-absentで衝突を処理。ホストの次へ操作はフェーズ識別子を検証し再送で飛ばしません。
- 公開応答は明示的な項目リストから組み立てます。回答中は本人の2問だけ、投票時は現在の2回答だけ、投票結果で初めて作者名を公開。TV指定は同じブラウザでも参加セッションを使いません。
- クライアントはゲーム進行中は応答完了後1.5秒間隔で同期。非表示タブとオフライン中は取得・ハートビートを停止し、復帰時に直ちに再取得します。待機・一時停止・終了画面、自動進行をオフにした結果発表・中間順位、回答の目安時間後で状態が変わらない場合は15秒後に5秒間隔、1分後に15秒間隔、15分後に完全休止し「再接続する」を表示します。回答の目安時間後は新しい期限や書き込みを繰り返さず、通常の取得だけで待ちます。手動の結果画面はカウントダウンと秒読み音を表示せず、主催者の「次へ進む」で進行・同期を再開します。TVも長時間休止後は再接続が必要です。期限切れ・存在しない部屋への取得は終了し、一時的な通信エラーは最大30秒間隔で再試行、15分変化がなければ休止します。投票の締め切りと自動の結果表示時間はサーバー時刻。期限到達を検知したAPIがサーバー側で次の状態を確定するためホストの短時間の切断中もテレビ/他の参加者で進行します。回答中は全員の確定か主催者を待ち、全画面を閉じても勝手に進みません。
- 同一ラウンドでランダムな巡回ペアを使い、奇数・偶数とも各自2人の異なる相手と対戦。過去の対戦回数が少ない巡回を選択します。出題はゲーム内重複なし、再戦にも履歴を引き継ぎ（選択ジャンルが不足する場合に再戦時リセット）、隣接ジャンルを分散。
- 100文字まで、NFKC・制御文字除去、JSONリクエスト4KiB上限、Origin検証、操作別IPレート制限。テキストはReactでエスケープ。レート制限は既存のインスタンス内方式であり、分散した大規模攻撃に対する全体上限ではありません。
- リアクションは専用の `POST /api/ogiri/[code]/reactions`（512byte上限、IPごと毎分480回の別枠で投票などの通常操作の枠を消費しない）。ルームを読んで本人認証・フェーズ・現在の手番を検証した後、部屋全体の書き換えではなく `reactions.counts.*` と `revision` のFirestore `increment` だけを書きます。同時に進行中のゲーム操作は更新時刻の条件付き保存で再読込・再試行するため、加算も進行も失いません。同じ手番の同一参加者は2.5秒に1回、1回の送信は種類ごと15まで。手番が変わった最初の送信で数をリセットし、参加者ごとの送信時刻は応答・TV・履歴へ出しません。新しいコレクションやpollはありません。
- 描画中の線は通信せず、送信時だけ数値ベクトルを保存します。512×384の整数座標・許可した6色（白の消しゴムを含む）/3太さ・最大64線/720点/8,000byteを検証し、SVG入力や任意の画像/HTMLは受け付けません。描画POST `/api/ogiri/[code]/drawing` だけ12KiB、通常操作は4KiBを維持します。最大24枚、ルームJSONは400,000byte以下。既存ルーム内の圧縮JSON文字列を使い、新しいコレクションや外部サービスは追加しません。
- 通常pollは絵IDだけを返し、ベクトルは含めません。`/api/ogiri/[code]/drawings/[id]` は現在の担当者の直前の絵/その手の自分の保存絵だけを公開前に取得でき、それ以外は403です（private/no-store）。チェーン公開後にだけ、その絵を閲覧できます。絵IDは更新ごとに変わり、端末は取得済みの絵を再利用します。各手の番号を操作トークンに含め、前の手から届いた遅い送信・確定・投票は409で拒否します。
- 絵つき履歴HTMLは検証済みの数値SVGとエスケープ済みの文字だけで生成し、JavaScriptや外部取得はありません。CSP `default-src none` を設定し、ダウンロード後はネット接続やルームの存続なしで表示できます。
- 最後のゲーム操作から8時間でAPIアクセス不可。Firestore TTL `deleteAfter` によって削除。TTL削除は即時ではなく通常24時間以内。通常回答の下書きは送信時に削除します。絵の伝言の下書きは、その端末・ゲーム・手ごとのキーで復元します。
- 履歴は専用の `ogiri_party_history/{128-bit random id}` に1ゲーム1文書を作成。ルーム更新の条件付きバッチと同時に確定し、再送・同時終了でも二重保存や再戦による上書きを防ぎます。本文は公開項目だけのJSON文字列で、秘密情報・投票者ごとの選択は含みません。進行中の通常APIには参照だけを載せ、履歴本文は配信しません。終了後の保存文書は変更しません。
- 履歴一覧はDB検索なし、詳細は開いたとき1文書だけ取得、pollなし。同じ端末の再閲覧には最大1時間のprivateブラウザキャッシュを使用。ダウンロードは取得済みデータから生成し追加通信なし。90日経過時点でAPI閲覧を止め、TTLで文書を自動削除します。専用コレクションのインデックスを無効化し、本文の索引ストレージを節約します。
- Firebaseルールの変更は不要。既存の本番Firestoreルールは一般利用者の直接読み書きを拒否し、管理者のみ許可します。既存RTDBルール、メダル、ランキング、ログインは変更しません。

## 運用

本番は既存VercelのmainデプロイとFirebaseサービスアカウント設定を使用。新しい有料サービスや外部生成APIは不要です。同期はWebSocketではなくHTTPポーリングなので、Firestore読み取りとVercel呼び出しは発生します（全画面が表示されゲームが進行し続ける10人+TV、20分の単純計算で約8,800回の取得と操作分。実際の間隔には応答時間も加わります）。放置した待機画面は1画面あたり15分間に100回未満の取得で休止するため、同じ15分を1.5秒固定で取得する場合の600回以上から削減します。ブラウザ側の停止は通常利用時の節約であり、直接APIを叩く攻撃の費用上限ではありません。IP制限はインスタンス内であり分散環境の全体上限ではなく、請求アラートやVercel Spend Managementなどの運用設定は別途必要です。

TTLの設定（当該コレクションだけに適用）:

```sh
gcloud firestore fields ttls update deleteAfter --collection-group=ogiri_party_rooms --enable-ttl --project=yudai-portfolio
gcloud firestore fields ttls update deleteAfter --collection-group=ogiri_party_history --enable-ttl --project=yudai-portfolio
gcloud firestore indexes fields update '*' --collection-group=ogiri_party_history --disable-indexes --project=yudai-portfolio
```

ゲーム設計・秘密情報の投影・公平なペア割り当ては独立した小さいモジュール。将来ゲーム用の汎用フレームワークは導入していません。

表示用フォントは [Dela Gothic One](https://github.com/google/fonts/tree/main/ofl/delagothicone) を固定UI文字とASCIIに絞ったWOFF2（54,444バイト）です。OFLは `public/fonts/ogiri-display-OFL.txt` に同梱。回答文・任意のプレイヤー名は端末の日本語フォントで表示し、外部フォントAPIを呼びません。吹き出しはHTML/CSSで描画。投票時は透過画像の「？」キャラが回答を話し、発表時に本人のキャラと名前へ切り替わります。吹き出しとキャラの登場・得点の動きは1回のみで、同じpollでは再開しません。動きの軽減設定では停止します。


合言葉の保存方式の根拠: [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt)、[Node.js scrypt](https://nodejs.org/docs/latest-v22.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)。合言葉と復帰コードの試行は既存の同じ部屋の30回/5分制限を共有し、重い照合の前に試行を永続化します。IPの24回/分制限も共有します。実ブラウザ回帰は任意の合言葉の設定、不一致/誤入力、閉じた後の別コンテキスト復帰、旧セッション失効、休憩維持、同じ3参加者で4ゲーム切替・通算・履歴保持を確認します。各ゲームの回答・投票全体の通し検証は既存テストが担当します。
