# 将棋AI強化ログ 2026-08(08-16開始、R3 arm A昇格まで随時追記)

対象: `/games/shogi` のブラウザ対局AI(HalfKP81 NNUE + WASM alpha-beta探索)。

このドキュメントは、codexによる10Mデータ収集run(PR #699)の失敗の事後検証から、
原因特定→本番モデルの再学習・昇格(PR #702)→反復蒸留パイプラインの構築→
蒸留ラウンド1〜3(R3で2度目の本番昇格)までの実験記録と教訓をまとめたもの。一次資料(receipt/log/weights)はすべて
`~/.codex/shogi-runs/` 配下の各runディレクトリに保存されている。

## 1. 出発点

- codexの研究run(2026-08-10〜13、`kingpair-interaction-10m-fast-v1-20260810`)は
  10M examples/epochの新教師データを完成させたが、2つの候補アーキ
  (DPA HalfKP96 / HalfKP64-RKI16)はいずれも**旧本番に0勝16敗**で完敗した。
- 敗北した候補がユーザー命令で強制デプロイされていたため、まずPR #701で
  旧本番(HalfKP81, weights SHA `25fc77ad…`)へ復旧した。

## 2. 事後検証: 0-16の原因(確定)

3つの独立調査(epoch-1対局 / trainer・データ実測 / 旧アーキ互換性調査)で原因を確定した。

1. **学習ターゲットの設計欠陥(主因)**: 新trainerは教師cpを生のまま
   `smooth_l1(pred, cp)` で回帰していた。旧本番の契約は
   `y = sigmoid(clamp(cp, ±3000) / 600)` + runtime K=600(`cp = raw_q × K / 8128`)で、
   この変換が丸ごと欠落していた。
2. **mateセンチネルの混入**: Aoba教師のmateスコアは±30,000ではなく**±999,98x(≈±10^6)**。
   fresh行の3.2%に混入し、value loss ≈25,900の約96%を占めていた。
   exact-onlyフィルタはboundの正確性の話であり、mate行を弾かない。
3. **K=1では出力レンジが物理的に不足**: 初期化std 0.01 + lr 5e-5 + 2 epochでは
   量子化後のモデル出力は実効±70〜80cpが上限。教師ラベルの約9割が表現不能で、
   評価関数はほぼ平坦になっていた(top1 0.03、全局詰まされて0-16は必然)。
4. **epoch-1も0勝16敗**(exportして実対局で検証)。epoch2の発散(pair loss 1.15→2.83)は
   副次的で、最初からターゲット設計で死んでいた。
5. trainerにはvalidationが無く`isfinite(loss)`のみだったため、完全に壊れたモデルが
   「2 epoch完走」として通過した。

**重要**: データ自体は無傷だった。監査済みの10Mコーパス
(legacy 2M + fresh親2M×4子=8M)は後続の全実験の基盤になった。

## 3. 本番モデルの再学習と昇格(PR #702)

### 5.1 インシデントと恒久対策(R2で発生)

1. **driver二重起動→shard二重書き込み**: 完全終端ゲームのみのprefix再構築で修復
   (1,417局保全)、mkdirロックで再発防止。
2. **固定深さ探索のライブロック(最重要)**: `--play-depth`の固定深さ探索には
   時間・ノード上限がなく、**約700局に1局の「病的局面」で1手の探索が55分を超える**。
   チャンク(≈55分)でkillされると、決定論的に同じゲームを最初から再生して
   また55分止まる無限ループになり、8ワーカー中4つが死に体になった。
   - 対策: 生成ツールのコピー版(`generate-nnue-selfplay-c.ts`)に
     `--max-game-wall-ms`(1局のwall-clock上限、採用値600,000ms=通常局中央値の約10倍)
     を追加。超過ゲームはterminal reason `deadline`・サンプル全破棄でスキップ
     (部分データは残さない)。fingerprintには正当な新パラメータとして反映。
   - 効果: 全ワーカー稼働に復帰し、306局/チャンク(過去最速)。deadline発動率~1.3%は
     事前予測(1/700×8)と整合。
3. **選択ツールの厳格チェックとの不整合**: target-parents未達で即死する仕様に対し、
   shortfall許容版(-c)を新設(選択意味論は不変)。

### 5.2 実測スループット(M4 Pro 14コア)

- 自己対局: ~5.5〜6.3局/分(8 workers、play-depth 4、~39 samples/局(sample-every 2))
- ラベリング: ~0.7s/親/worker(depth12 MultiPV4)。生成との並行走行(4 workers)で
  壁時間をほぼ隠蔽できる
- 12ワーカー並行(8+4)はネット+6%程度(E-coreの寄与が小さい)。**真の短縮は
  ラベリングの前倒し重畳**で得られる

### 6.1 実行アーキテクチャ(3日級ジョブの無人運転)

単発コマンドでは回らない長さ(70時間超)のため、次の構成で無人運転している。

- **チャンク駆動**: すべての長時間工程を約55分のチャンクに分割し、
  `chunk-driver-c.sh` が「現在の状態を確認→次の1チャンク(自己対局続行/
  tranche構築/ラベラー続行)を起動→`state.json` 更新」を1呼び出しで行う。
  各工程は再開可能設計(自己対局=progress.jsonl、ラベラー=完成shard自動スキップ、
  選択=create-only)なので、プロセスkillに耐える。二重起動はmkdirロックで防止。
- **状態の完全ファイル化**: 進捗は `state.json`、運用知識は `handoff.md` に常時
  反映され、**どのセッション・どのエージェントからでも即再開できる**。
- **世代交代エージェント**: 駆動役のAIエージェントはwake-upを繰り返すごとに
  コンテキストを消費するため、driver呼び出し30回ごとに handoff.md を更新して
  後任へ交代する運用にした(1〜5代目まで交代済み、交代コストはほぼゼロ)。
- **工程の重畳**: 自己対局と並行して、6,000局ごとのtranche(t1〜t4)で
  親選択→Aobaラベリングを先行消化する。ラベリングの壁時間はほぼ生成に隠蔽される。

### 6.3 最終結果(2026-08-23確定): 引き分け — チャンピオン防衛

全工程が完走した(2026-08-19開始、約80時間の無人運転、駆動agentは5世代交代)。

- **自己対局**: 24,105局 / 924,773局面。deadline打ち切り347局、エンジンクラッシュ0。
- **選択+ラベリング**: disjoint親 **600,000(capちょうど)**、exact率86.1% →
  exact親516,401、**新規子 2,065,163行**(val衝突6・重複435を除外)。
- **学習**: 合計12,341,977行(蒸留シェア19.6%)、チャンピオンと同一レシピ・同一init。
  val loss 0.014469 / MAE 324cp(チャンピオンの0.014462 / 327cpと同等)。
- **ゲート(1000ms/手 × 80局、5 seed)**: **40勝1分39敗 = 50.6%、
  Wilson 95% CI [39.9%, 61.3%]** — CI下限が50%に届かず**不合格。チャンピオン交代なし**。

**結論**: R1(シェア3.6%→50.0%)とR2(シェア19.6%→50.6%)を併せると、
**depth 12教師による自己蒸留は、データ量をいくら積んでも現チャンピオンを
改善しない**ことが強く示唆される。現モデルはこの教師品質(Aoba depth 12)の
信号をすでに飽和吸収しており、律速は**データ量ではなく教師の質(探索深さ)**。
次に試す価値があるレバーは (a) 教師ラベルのdepth 16-20化(ラベリングコスト
約5倍/親)、(b) より大きなネット(ブラウザ推論速度とのトレードオフ)、
(c) df-pn詰みソルバー(Elo小・UX大)。

**2026-08-24追記**: この「律速はデータ量ではなく教師の深さ」という読みは、R3で
**部分的に否定された**。同じdepth 12教師でも、親を中盤ではなく定跡離脱直後に
差し替えるだけでチャンピオンを明確に上回った(§7)。飽和していたのは
「depth 12という教師品質」ではなく「R1/R2が繰り返し掘っていた中盤という位置」だった。
深さ単独の寄与はR3 arm B(depth 18、同一親集合)で分離測定中。

副産物として、80時間級ジョブの無人運転基盤(チャンク駆動+状態ファイル化+
エージェント世代交代)とdeadline付き自己対局生成器は今後のラウンドにそのまま
再利用できる。

## 7. 蒸留ラウンド3(R3、2026-08-24): 定跡末端蒸留 — 昇格(PR #711)

R1(蒸留シェア3.6%)50.0%、R2(19.6%)50.6% と、**量を積んでも動かなかった**。
R3はここで仮説を切り替えた。

### 7.1 仮説: 飽和しているのは「中盤」であって「離脱直後」ではない

R1/R2の親はいずれもチャンピオン自身の自己対局の中盤局面だった。
その帯はすでに約10Mの教師で埋まっており、depth 12教師の信号を吸い尽くしている。
一方、**実戦で定跡が切れる地点(book末端とその直後)は、誰も明示的に教えていない**。

事前測定で前提を確認した(`selection-50k/overlap-report.json`)。

- book v3 は173,172局面。初期局面から定跡手のみで到達可能なのは122,326局面。
- その **葉 = 43,884局面**、**離脱局面(葉の子=実戦で最初に定跡を外れる局面)= 72,366局面**。
  重複を除くとユニーク116,250局面(葉のply分布2〜31、離脱は3〜32でply22に山)。
- **このうち86.4%(100,468局面)が既存学習データに存在しない**。
  champion train 9.9M行との衝突は12,515件、R1/R2の選択との衝突は各数十件しかない。

つまり「未学習の分布」が実在し、しかも**必ず毎局通過する帯**だった。

### 7.2 設計(R1/R2とレシピは同一、変えたのは親の選び方だけ)

- 親: 選択可能な100,443局面からハッシュ順で **50,000をパイロット選択**(残り50,443は規模拡大用に温存)。
  除外セット(既存学習・sealed・R1/R2の親子ID)はR1/R2と同じフィルタを通す。
- 教師: Aoba **depth 12 MultiPV4 exact-only**(arm A)。196シャード、exact親43,710。
- データ: 新規子 **166,211行**(val衝突45・base重複4,544・arm内重複4,040を除外)。
  R2 trainの12,341,977行に加算して **12,508,188行、蒸留シェアはわずか1.33%**。
- 学習: チャンピオン/R1/R2と**同一のbase checkpoint**(`halfkp81-g3-full-all-seed42/epoch2.pt`)から
  warm-start、同一レシピ(sigmoid target / K=600 / cp-clamp 3000 / lr 5e-5 / 4 epochs /
  batch 1024 / seed 42)。val loss 0.014501、MAE 325cp、pair_acc 0.8997(チャンピオン級で有意差なし)。
- export: **94,656,708 bytes / k_sigmoid=600**、SHA `f4771786…`。ランタイム契約は不変。

### 7.3 測定器を作り直した(これが無ければ空振りしていた)

R1/R2が使ったゲート(`wasm-spike/match-nnue-vs-v3.ts`)は
**「ランダム6手で開始・定跡無効・詰みソルバー無効」**。
定跡を切っているので、**R3が学習した離脱帯を1局も通らない**。
そのまま流用すれば「効果ゼロ」という嘘の結論が出る構造だった。

対策として **targeted gate**(`tools/gate-bookexit.ts`)を新設した。
初期局面から**held-out**の離脱局面までの実際の指し手列を再現してから両者に自力探索させる。
学習選択に入っていない離脱局面(ply 10〜24)から40個を選び、先後入れ替えで80局。

**ノイズ床の事前確認(A/A対照)**: 同一条件でチャンピオン同士を80局戦わせ、
**39勝1分40敗 = 49.4%、Wilson 95% CI [38.7%, 60.1%]** を得た。
ハーネスに系統的な先後・順序バイアスが無いことを確認したうえで本番測定に入った。

### 7.4 結果: arm A(depth 12)が明確に勝った

| ゲート | 条件 | 結果 | Wilson 95% CI |
|---|---|---|---|
| **targeted(主判定)** | 定跡離脱起点40局面×先後=80局、1000ms/手 | **53勝27敗 = 66.2%** | **[55.4%, 75.7%]** |
| 標準(R1/R2互換) | curated openings、1000ms/手、5 seed×16局=80局 | **51勝2分27敗 = 65.0%** | [54.1%, 74.6%] |
| A/A対照 | チャンピオン同士、targetedと同条件80局 | 39勝1分40敗 = 49.4% | [38.7%, 60.1%] |

- 主判定・副判定ともCI下限が50%を明確に上回り、**採用条件を満たした**。
- 標準ゲートは**5セット全勝ち越し**(10-6 / 9-7 / 9-5 / 10-6 / 13-3)。
  seed依存の偶然ではない。
- 副次指標(離脱から10手以内の駒損イベント率)も新モデル 0.05/局 vs チャンピオン 0.062/局。
- 学習した帯(targeted 66.2%)だけでなく**通常の戦型でも同等に勝っている**(65.0%)ため、
  離脱直後の改善が中盤以降へ波及していると読める。

### 7.5 R1/R2との対比 — 効いたのは量ではなく位置

| ラウンド | 親の出所 | 蒸留シェア | 標準ゲート | targeted gate |
|---|---|---:|---|---|
| R1(08-19) | 自己対局の中盤 | 3.6% | 50.0%(48局、引き分け) | 未実施 |
| R2(08-19〜23) | 自己対局の中盤(子の量は5.8倍) | 19.6% | 50.6%(80局、引き分け) | 未実施 |
| **R3 arm A(08-24)** | **定跡末端・離脱直後** | **1.33%** | **65.0%(80局、昇格)** | **66.2%(80局)** |

R1/R2と直接比較できる**標準ゲート同士で見ても 50.6% → 65.0%(+14.4ポイント)**である。
R2はR1の5.4倍のシェアを投入して0.6ポイントしか動かなかったのに対し、
R3はR2の**1/15のシェア**で14ポイント以上動かした。
**「どれだけ足すか」ではなく「どこを足すか」が律速だった**、というのが本ラウンドの結論。
R2の§6.3で「律速は教師の質(探索深さ)」と書いたが、少なくとも**位置の選択が
深さより先に効く**ことがこれで判明した(深さの寄与はarm Bで分離測定中)。

### 7.7 arm B(depth 18)の結果: **不合格 — 深さのレバーは死んだ**

R3は同一の親集合に対して **depth 12(arm A)と depth 18(arm B)** の両方をラベルし、
「位置を絞った効果」と「教師の深さの効果」を分離する設計になっている。
arm Bのラベリング実測は 4.46 s/親 = d12(0.586 s/親)の **7.6倍**。

| arm | 教師 | exact率 | 蒸留シェア | 定跡離脱ゲート | 通常ゲート | 判定 |
|---|---|---|---:|---|---|---|
| **A** | depth 12 | 87.4% | **1.33%** | **66.2%** [55.4, 75.7] ✅ | **65.0%** [54.1, 74.6] ✅ | **採用** |
| B | depth 18 | 96.2% | 1.46% | 61.9% [50.9, 71.7] ✅ | 53.1% [42.3, 63.7] ✗ | 不採用 |

(各80局、1000ms/手、対チャンピオン `e04e60c7…`)

**教師との一致率は 87.4%→96.2% と大きく上がったのに、強さには繋がらなかった。**
arm Bは定跡離脱ゲートこそ通ったが、通常ゲートでCI下限が50%を割り、採用条件
(両ゲートともCI下限>50%)を満たさない。

これで **§6.3 でR2が「次の本命」と結論づけた「教師ラベルのdepth 16-20化」は否定された**。
ラベリングコスト7.6倍を払う根拠は無い。R2の結論のうち生き残ったのは
「データ量を増やしても効かない」の部分だけで、代わりの答えは深さではなく**位置**だった。

なお注意点として、arm Aのゲートはdepth 18ラベリングが8コアを占有した状態で、
arm Bのゲートは空いたマシンで走った。各ゲートは同一プロセス内で両エンジンが
交互に指すペア設計なので**チャンピオン比の各結果は有効**だが、A対Bの直接比較は間接的である。

### 7.8 昇格作業で判明したこと: 「病的局面」は評価関数ごとに変わる

昇格PRのCIで、回帰テスト「飛車先歩打ちループ」(固定depth 11で8手継続対局)が
**タイムアウトで落ちた**。精査した結果、**ループ再発ではなく探索コストの問題**だった。

| | 前チャンピオン | R3 arm A |
|---|---|---|
| 当該ループ局面から8手・固定depth 11 | **約8秒** | **約172秒**(CIランナーでは約350秒) |
| 初期局面 depth 11 | 354ms | 381ms |
| 通常の序盤8手後 depth 11 | 816ms | 634ms |

つまり**中立な局面の探索速度は不変**(むしろ僅かに速い)で、
**この1局面でだけ探索木が約20倍に膨らむ**。§5.1で記録した
「固定深さ探索は約700局に1局の病的局面で暴走する」現象そのもので、
**どの局面が病的かは評価関数が変わると変わる**というのが今回の新しい知見。

判定と対応:
- **ループ自体は再発していない**(千日手ゼロ、`P*8f`は1回のみ)。契約は満たしている。
- 本番は固定深さ探索を一切使わない(ブラウザは1000ms時間制御)。1000ms×240局の
  ゲートで新weightsが勝っている以上、実プレイへの影響はない。
- したがって**アサーションは一切緩めず、テストの制限時間だけを900秒に引き上げた**。
  継続手数を削って時間内に収める対応は取らない(それは検証内容を薄める)。

### 7.9 スコアボード: どの変更がどれだけ効いたか

本番に入った変更(すべて直接対局で実測。static指標は判定に使っていない):

| # | 変更 | 測定条件 | 結果 | Elo換算 |
|---|---|---|---|---|
| ① | NNUE再学習(PR #702) | vs 旧本番、80局/1000ms | 48勝3分29敗 = **61.9%** [50.9, 71.7] | **+84** |
| ② | 定跡v3 + master安全弁(PR #709) | 定跡離脱手数 / 駒損イベント | 7.91→8.66手、駒損 0.53→**0.25**/局 (p=0.024) | 測定不能※ |
| ③ | expert/hard安全弁(PR #710) | 192ペア×2難易度 | 有意差なし(害もなし) | ±0 |
| ④ | R3定跡末端蒸留(PR #711) | vs ①、80局×2条件 | **66.2%** [55.4, 75.7] / **65.0%** [54.1, 74.6] | **+107〜117** |

※②は定跡の改善であり、エンジン同士のA/Bでは原理的に測れない(両者ともすぐ定跡を抜けるため)。

実際、作者(二段)が「明らかに強くなった」と体感したのは②の直後だった。

## 8. 教訓(2026-08分の追記)

1. **検証指標(val loss / pair_acc / MAE)は採用判定に使わない。** ゲートは常に
   本番時間制御(1000ms+)の直接対局、有意性はWilson CIで判定する。
2. **教師スケールとruntime契約(K、clamp、センチネル処理)は一体で検証する。**
   ターゲット変換の欠落は「学習は完走するが完全に弱い」モデルを生む。
3. **trainerには最低限のvalidationを入れる。** `isfinite`だけでは全損を検出できない。
4. ~~**数%の増分データは飽和モデルを動かさない。**~~ **← R3で反証。**
   R1/R2時点ではそう見えたが、R3が**シェア1.33%**で+110 Elo相当を出したことで、
   正しくは「**中身が既存データと同じなら**、数%どころか2割足しても動かない」だと判明した。
   教訓9を参照。
5. **warm-startは強さだけでなく量子化親和性でも有利。**
6. **固定深さ探索を無人パイプラインに使うなら、wall-clock上限が必須。**
   病的局面は~1/700局の頻度で必ず出る。
7. **長時間ジョブは「チャンク実行+ファイル永続化された状態+再開可能な設計」で組む。**
   すべての工程(生成・選択・ラベル・学習・対局)がこの形なら、プロセスkillや
   エージェント交代に耐える。
8. **並列化はコア数の壁より工程重畳が効く。** 生成とラベリングの並行走行が最大の短縮。
9. **「量が足りない」と結論する前に「位置が違う」を疑う。** R1→R2はシェアを5.4倍にして
   0.6ポイントしか動かなかったが、R3はシェア1.33%で14ポイント以上動かした。
   増分データの効き目は**総量ではなく、既存データが薄い分布をどれだけ突いたか**で決まる。
   新ラウンドの設計は、まず**候補局面と既存学習データの重なりを実測する**ことから始める(R3では86.4%が未収録と確認できた)。
10. **ゲートは「学習した分布を通る」ものでなければ測定器にならない。** R1/R2のゲートは
   定跡を無効にしてランダム6手から始めるため、R3が学習した定跡離脱帯を1局も通らない。
   流用していれば「効果ゼロ」という嘘の結論が出ていた。
   新しい狙いを立てたら**ゲートも一緒に設計し直し、A/A対照でノイズ床を先に測る**。
11. **自己対局は蒸留の必須工程ではない。** 親の供給源を定跡(既存資産)に替えると、
   R2の約70時間の自己対局が丸ごと不要になり、ラウンド全体が80時間→半日になった。
12. **固定深さ探索に依存する回帰テストは、weights差し替えのたびに壊れうる。**
   病的局面は評価関数ごとに変わるので、同じ局面の同じ深さが20倍重くなることがある(§7.8)。
   落ちたときは**まずアサーションが破れたのか制限時間が尽きたのかを分ける**こと。
   前者なら本物の回帰、後者なら中立局面での探索速度を測って全体退行でないことを確かめ、
   **検証内容ではなく制限時間の側を直す**。
13. **教師の探索深さを上げても強くならない(R3 arm Bで実証)。** depth 12→18 は教師との
   一致率を 87.4%→96.2% に上げるが、対局では通常ゲートのCI下限が50%を割った。
   ラベリングコストは7.6倍。**R2が「次の本命」と挙げた深さのレバーはこれで閉じた。**
   教師の再現精度を上げることと、探索と噛み合う評価を学ぶことは別問題である
   (サイクル1の「教師近似の質は強さを予測しない」の再確認でもある)。
